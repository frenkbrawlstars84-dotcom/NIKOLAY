# Николай — портфолио веб-разработчика

NIKOLAY — Digital Experience. React, TypeScript, Vite, Tailwind CSS 4, Motion, Three.js / React Three Fiber, Drei и GSAP ScrollTrigger. Процедурная WebGL-скульптура, пространственная галерея и пять интерактивных демонстраций. Системные шрифты не требуют внешних запросов. Анимации учитывают `prefers-reduced-motion`.

## Тактильные взаимодействия

Существующий маршрут сохранён: металлический портал → коридор → одна чёрная дыра TON 618 → полёт среди галактик → проекты. Новый длинный обязательный экран не добавлен. Аккреционный диск рассчитывается процедурно в разрешении Canvas, с дополнительным изображением обратной стороны при линзировании; размытие не подменяет детали.

Портал, металлический узел, стеклянный кристалл и экраны проектов реагируют на наведение и нажатие. Клик или касание раскрывает форму; повторное нажатие возвращает её. Enter/Space выполняют то же действие, Escape возвращает исходную форму, стрелки вращают узел и кристалл. Перетаскивание не считается кликом, вертикальная прокрутка на сенсорном экране сохраняется. Одна пружина управляет каждой формой без очередей конфликтующих tween. При погружении в портал управление переходит прокрутке; масштаб ограничен выделенной областью.

Кубик выполняет шесть ходов и их точные обратные движения, с четверть-поворотом за 0.34 с и паузой 1.35 с между циклами. Нажатие добавляет короткую трёхходовую комбинацию и её обратную последовательность; повторные нажатия объединяются в одну дополнительную комбинацию. Текущий цикл сначала завершается. Геометрия не пересоздаётся в кадре, обновляется quaternion группы слоя. Белые накладки и тонкие чёрные разделители сохранены, отдельных кнопок кубика нет.

Проверки: `npm run test:models` (19 тестов), `npm run test:browser` (dev/production и отказы WebGL), `npm run test:tactile` (новые жесты, клавиатура, повторные нажатия, мобильный viewport и reduced motion). Браузерные команды требуют Chromium: в этой среде задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium`. Полные результаты и ограничения — в `docs/QUALITY_REPORT.md`.

## Запуск

Требуется Node.js 22+ и npm.

```sh
npm install
npm run dev
```

Vite выводит адрес сервера в терминал. Для проверки публикации:

```sh
npm run build
npm run preview
```

Сборка находится в `dist`. В ограниченной облачной среде при недоступном стандартном кеше используйте `npm install --cache /tmp/nikolay-npm-cache`. Для повторяемой установки с lockfile можно использовать `npm ci`.

Проекты редактируются в `src/projects.ts`. Поля: `name`, `description`, `category`, `technologies`, `url`, `image`, `upcoming`. Основной контент находится в `src/main.tsx`, стили — в `src/style.css`. SEO-заголовок и описание — в `index.html`. После появления домена можно добавить canonical и абсолютные `og:url` / `og:image`.

## Публикация на Netlify

1. Загрузите проект в свой GitHub-репозиторий и подключите его в Netlify через импорт существующего проекта.
2. Команда сборки: `npm run build`, директория публикации: `dist`. Эти настройки уже указаны в `netlify.toml` вместе с Node.js 22.
3. В настройках переменных окружения Netlify добавьте `VITE_TELEGRAM_URL`.
4. Запустите Deploy. После изменения переменных выполните новую сборку.

Также можно загрузить готовую папку `dist` через ручную публикацию Netlify. В этом случае контакты должны быть заданы перед локальной сборкой.

## 3D и анимации

В `src/Scene.tsx` — настоящая процедурная WebGL-сцена. Один Canvas сохраняется на протяжении hero и пространственного перехода. GLSL-шейдер превращает исходную спираль в цифровой коридор глубиной 38 условных единиц; камера проходит туннель и затем пересекает горизонт TON 618, частицы остаются в трёхмерном пространстве. Формой и камерой управляет прогресс прокрутки, а не только прошедшее время.

`src/useCinematicFlow.ts` задаёт порядок сцен: текст hero уходит под маску, затем открывается весь viewport, линии разворачиваются в коридор, и из движения появляется следующая секция. Начальный viewport измеряется по отдельной области справа от текста (на мобильных — под ним). Спираль не рисуется поверх основного текста. Нативная прокрутка сохраняется, перехвата колеса мыши нет. При высоте экрана до 650 px длинные закреплённые переходы заменяются обычной прокруткой и ручной навигацией галереи.

`src/ProjectGallery.tsx` — пространственная галерея HTML-плоскостей с перспективой и глубиной. Прокрутка проводит через три проекта; кнопки и стрелки позволяют выбрать нужный напрямую. Hover наклоняет всю поверхность и отдельно сдвигает изображение. Неактивные плоскости исключены из клавиатурной навигации. Изображения не подменяются фальшивыми скриншотами.

`src/FluidText.tsx` раскрывает главные заголовки через волнообразную polygon-маску и короткий хромированный блик по буквам. Эффект выполняется один раз. После завершения удаляются clip-path, filter, transform и will-change, блик скрывается; остаётся чёткий HTML-текст. Основной текст не искажается. При reduced motion заголовки сразу показаны без эффекта.

### Производительность и доступность

Сцена загружается отдельным динамическим модулем. Desktop: 76 линий × 168 сегментов, 220 частиц, DPR не выше 1.5, до 60 кадров/с. Mobile / мало ядер CPU: 36 × 104, 80 частиц, DPR=1, до 30 кадров/с. На сцену приходится два draw calls (линии и точки); дорогих постэффектов нет. Вне экрана, в скрытой вкладке и по PAUSE непрерывный рендер останавливается. Геометрия и материалы освобождаются при размонтировании.

При `prefers-reduced-motion` 3D и фон статичны, закреплённых scroll-проходов нет, слова не искажаются, проекты переключаются кнопками без наклонов. Без WebGL2 или при ошибке Canvas доступна статичная SVG-графика, содержание и ссылки работают.

`src/AmbientBackground.tsx` добавляет периферийные частицы и мягкие световые линии одним 2D-canvas без второго WebGL-контекста. Центр оставлен свободным для чтения. Фон также учитывает PAUSE, скрытую вкладку, мощность устройства и reduced motion.

Все эффекты работают локально, без платных API и внешних 3D-моделей. Vite может предупреждать о размере динамического 3D-модуля, содержащего Three.js: это не ошибка сборки. Скорость на реальных телефонах зависит от GPU; эмуляция мобильного viewport в Chromium не заменяет проверку на физических устройствах.

## Исправление чёрного экрана в режиме разработки

Причина была в `useCinematicFlow.ts`: при повторном запуске / очистке эффектов в React StrictMode GSAP вызывал функцию вычисления `clipPath`, а та читала `anchor.current!.getBoundingClientRect()`. Ref к этому моменту уже мог быть `null`, исключение размонтировывало React-приложение целиком. В production-preview очистка эффектов не повторяется так же, поэтому одной сборки для обнаружения было недостаточно.

Теперь эффект захватывает свои DOM-элементы, проверяет подключение к документу и при очистке возвращает последнее корректное значение маски. Callback ResizeObserver защищён от работы после удаления эффекта. StrictMode сохранён.

`SceneLayer.tsx` изолирует ленивый импорт 3D-модуля внешним ErrorBoundary. Статичный SVG fallback из `SceneFallback.tsx` доступен независимо от Three.js. Неподдерживаемый WebGL, ошибка renderer / шейдера, потеря GPU-контекста или запуск, не завершившийся за 10 секунд, отключают только 3D. Пока реальный первый кадр не отрисован, контент не скрывается ради пространственного прохода. При отказе сцены закреплённый проход отключается, текст восстанавливается, все ссылки и галерея доступны. Canvas не перехватывает события мыши.

## Космическая атмосфера и акцентные сцены

`src/AmbientBackground.tsx` процедурно создаёт текстуры туманностей на небольшом offscreen-canvas, затем плавно смещает их за контентом. Здесь же — 150 далёких звёзд с разной глубиной, мягким мерцанием и parallax, а также периферийные световые линии. Никаких фотографий, сторонних изображений или платных API. На мобильных и устройствах с малым числом ядер остаются один слой облаков и 55 звёзд, обновляемых не чаще 12 раз/с; desktop-фон ограничен 25 обновлениями/с. Текст hero защищён мягкой тёмной подложкой, а viewport спирали по-прежнему отделён от текста.

`src/AccentObject.tsx` загружает `AccentScene.tsx` только при приближении к секции. В «Обо мне» — хромированная скульптура непрерывной формы; в контактах рядом с @yuniorqq — настоящий 3D-кубик Рубика. Он состоит из 26 скруглённых деталей и 54 белых накладок. `src/rubikRig.ts` разделяет неподвижную часть и временную группу поворачиваемого слоя: два instanced draw calls в покое, четыре во время поворота. Геометрия и материалы общие; отдельные слои поворачиваются на 90° и сохраняют новое положение. Все наружные грани белые, между ними — тонкие чёрные разделители; свет и отражения создаются локально. На мобильных и слабых устройствах все скульптуры сохраняют настоящую 3D-геометрию с меньшей детализацией; статичный fallback используется при ошибке WebGL или загрузки модуля. DPR ограничен диапазоном 1–1.25 на мобильных и 1–1.5 на desktop, antialiasing включён. Пока сцена видна, R3F рендерит её на каждом доступном кадре браузера: прежний ограничитель 24/45 FPS удалён. Анимация выполняется в `useFrame`, без обновления React state.

У каждой новой сцены собственные ErrorBoundary, таймаут запуска и независимый SVG fallback. Общий `src/CanvasHealth.tsx` следит за ошибками шейдера и потерей GPU-контекста. Ошибка кубика не отключает основной сайт и не скрывает Telegram. Вне viewport, в скрытой вкладке и по глобальной PAUSE рендер останавливается. При reduced motion звёзды и все 3D-объекты статичны; `src/useReducedMotion.ts` также отслеживает переключение настройки во время просмотра. Геометрия, материалы, instance-буферы и сгенерированные reflection-текстуры освобождаются при размонтировании.

Браузерный регрессионный тест дополнительно проверяет отказ загрузки AccentScene и потерю WebGL-контекста кубика. Дополнительно в Chromium проверены мобильная композиция, отсутствие пересечения спирали с текстом и остановка instanced draw calls при PAUSE / уходе кубика за экран. Показатели плавности на физических устройствах зависят от GPU.


## TON 618 и точные повороты кубика

`src/BlackHole.tsx` использует тот же WebGL-контекст, что и спираль hero. Прежняя геометрия из концентрических линий удалена. GLSL-шейдер использует аналитическую аппроксимацию гравитационной линзы, пересечение луча с наклонённой плоскостью диска и поглощение света центральной областью. Он создаёт искажённое изображение обратной стороны диска над и под центром без тяжёлого итерационного raymarching на каждом пикселе. Это кинематографическая визуализация, а не научный симулятор. У газа процедурная турбулентность и дифференциальное вращение; свечение белое и серебристое. Отдельный облегчённый композит добавляет мягкий bloom. Контур центральной области сглаживается через экранные производные GLSL. Далёкие звёзды тоже искажаются линзой; пространственные частицы остаются в существующей 3D-сцене. Внешних текстур и изображений нет.

`src/tonTravel.ts` задаёт конечный, обратимый путь камеры: 0–25% — дальний вид, 25–55% — приближение, 55–80% — крупный план, 80–100% — пересечение горизонта и выход. Это прогресс самого полёта после читаемого вступления со спиралью. Между этапами непрерывна скорость камеры. GSAP ScrollTrigger связывает путь с обычной прокруткой в обоих направлениях. Краткое затемнение ограничено контейнером перехода, не перекрывает меню и не блокирует прокрутку. После выхода появляется галерея проектов; «Обо мне» сохранён после неё. Общая длина прохода — 245svh (220svh на мобильных), дополнительного scroll-lock нет.

Базовый буфер TON совпадает с физическим разрешением Canvas, включая Full HD и QHD. Прежнее уменьшение разрешения вдвое и ограничение ширины 640/1100px удалены: основной диск и тёмный контур не растягиваются из маленького изображения. Размытие добавляется только к свечению поверх чёткой базы. DPR основной сцены — 1 на мобильных и до 1.25 на desktop. Детализация газа и звёздного поля одинакова на desktop и мобильных; на мобильных сокращено число геометрических нитей, частиц и выборок слабого bloom. Статичных изображений и загружаемых текстур у TON нет. При отказе шейдера, framebuffer или контекста включается SVG fallback и отключается кинематографическая маска, сохраняя HTML-контент. При reduced motion и низком viewport длинный проход отключён. Буфер, геометрия и материалы освобождаются при размонтировании.

`src/rubikModel.ts` хранит 26 деталей на целочисленной сетке и дискретные матрицы ориентации. В начале поворота 9 выбранных деталей и их накладки переносятся в отдельный batch временной группы. Во время поворота меняется только quaternion этой группы; instance-матрицы пересчитываются на границах поворота, а не каждый кадр. Используется quintic easing с нулевой скоростью и ускорением на концах, поворот длится 1.8 с, пауза между слоями — 6.5 с; в конце выполняется один точный поворот на 90°, а новая позиция фиксируется. Автоматическая последовательность меняет оси и слои, не откатывая каждый поворот назад. Визуальная область кубика увеличена до 400px в desktop-композиции и отцентрирован в своей области; на телефоне он расположен над отцентрированным Telegram. Кнопок и панелей управления кубиком нет. Медленное вращение и реакция на курсор сохранены; при reduced motion объект статичен. Email отсутствует; @yuniorqq, прямая ссылка и кнопка связи ведут на https://t.me/yuniorqq.

Проверка математики кубика и пути камеры отдельно:

```sh
npm run test:models
```

Тесты проверяют 26 деталей и 54 наружных накладки, обратный поворот, возврат после четырёх поворотов, сохранение решётки после 2 000 смешанных поворотов, монотонность пути камеры и непрерывную скорость на границах этапов. Отдельная проверка настоящих Three.js-групп подтверждает отсутствие скачка при фиксации слоя, сохранение 26 позиций после 200 поворотов и неизменность instance-буферов на промежуточных кадрах.

`npm run test:browser` проверяет фактическое разрешение буфера TON относительно Canvas и реальные GPU-вызовы кубика: 17 неподвижных + 9 вращающихся деталей, всего 54 белые накладки, отсутствие загрузки instance-матриц каждый кадр, antialiasing и остановку рендера при reduced motion. Также проверяются dev/production, мобильная композиция, быстрая / медленная / обратная прокрутка TON и отказ его шейдера без потери остального сайта. Облачный Chromium использует программный WebGL; замеры частоты кадров в нём не подтверждают производительность на физическом GPU пользователя.

### Настоящие скриншоты проектов — обязательный незавершённый пункт

В этой облачной среде сетевой прокси возвращает 403 на оба домена Netlify. Реальные снимки пока не получены: в `public/projects/screenshots.json` нет записей, на поверхностях панелей показаны честно подписанные обложки «не скриншот». Эти обложки не следует считать выполнением требования о реальных скриншотах.

Необходимо разрешить в настройках сети среды:

- `amazing-pony-95fbe1.netlify.app`
- `lambent-pudding-e679ea.netlify.app`

После появления доступа снимки создаются существующим Playwright без новых зависимостей:

```sh
npm run capture:projects
npm run check:captures
npm run build
```

Скрипт `scripts/capture-projects.mjs` сначала проверяет HTTP-доступ, затем открывает каждый настоящий сайт в браузере, проверяет название бренда и снимает viewport 1600×1000. Ошибочную страницу он не сохраняет как скриншот. Оптимизированные WebP (1600×1000, quality=0.9), SHA-256 исходного снимка и источник/время захвата записываются в `public/projects`; галерея автоматически подключает их из манифеста при сборке. Для браузера, установленного в облаке, используется `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium`; на Windows перед первым захватом можно выполнить `npx playwright install chromium`.

Проверка `npm run check:captures` сейчас намеренно сообщает об отсутствии двух обязательных снимков. Она должна пройти после их фактического получения. Общий браузерный тест проверяет три Canvas, реальные матрицы вращения при перетаскивании/нажатии стрелок, физические uniform-параметры стекла, наклон экранов, единственную активную сцену, мобильный DPR, остановку невидимых сцен и независимые fallback.


## Непрерывное путешествие и контроль качества

Спираль в `src/Scene.tsx` теперь действительно превращается теми же вершинами в продольный пространственный коридор. Это не набор замкнутых концентрических колец. Камера движется по конечному обратимому пути из `src/tonTravel.ts`, в глубине постепенно открывается TON 618. Настоящие звёздные отрезки на разных глубинах создают optic flow. Нити искривляются возле горизонта; геометрия за тёмным центром отсечена аналитической маской, чтобы не просвечивать сквозь него. При приближении нити исчезают плавно, оставляя диск главным объектом. Нативная прокрутка и существующая длина прохода сохранены.

В `src/BlackHole.tsx` уменьшены суммирование света, экспозиция и bloom; вместо больших белых пятен видны отдельные газовые нити. Буфер по-прежнему равен разрешению Canvas, все четыре октавы газа сохранены и на телефонах. У звёзд два слоя глубины с независимым смещением. Углы звёздного поля рассчитываются один раз на луч, вращение газа использует матрицу вместо цепочки atan → sin/cos. Полноэкранные маленькие растровые изображения не используются.

Выбранный проект в `src/ProjectScreenScene.tsx` выходит вперёд, слегка увеличивается и сопровождается изменением ракурса камеры. Экран использует MeshBasicMaterial без экспозиции освещения; активный снимок сохраняет исходную яркость. Текстуры имеют sRGB и anisotropy до 8. Высота сцены учитывает высоту viewport, чтобы кнопки не уходили под край закреплённой галереи.

Кубик по-прежнему вращает временную группу слоя. Контроллер переносит остаток времени между паузой и поворотом, сохраняя одинаковый результат при разных интервалах кадров. Возобновление после паузы начинает с нулевого delta; середина поворота не сбрасывается, instance-буферы при паузе не пересобираются. В браузерную регрессию добавлена эта проверка.

Когда видна активная WebGL-сцена, атмосферный 2D-фон сохраняет последний кадр. Это освобождает ресурсы для основного объекта; в секциях без активной 3D-сцены фон продолжает движение. Качество TON не уменьшается ради FPS.

Для повторяемого короткого профиля запустите preview, затем в другом терминале:

```sh
npm run profile:scenes -- sample http://localhost:4173
```

Скрипт измеряет кадры реального WebGL-рендера, requestAnimationFrame, long tasks и CDP Script/LayoutDuration отдельно для TON и кубика. JSON и PNG сохраняются во временную папку ОС; её можно переопределить через `NIKOLAY_PROFILE_DIR`. Для облачного Chromium задаётся `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium`.

Результаты и ограничения текущей проверки записаны в `docs/QUALITY_REPORT.md`. Эти измерения нельзя выдавать за подтверждение 60 FPS на физическом GPU. Реальные скриншоты проектов остаются обязательным незавершённым пунктом до разрешения двух Netlify-доменов или получения снимков от владельца.
