# Николай — портфолио веб-разработчика

NIKOLAY — Digital Experience. React, TypeScript, Vite, Tailwind CSS 4, Motion, Three.js / React Three Fiber, Drei и GSAP ScrollTrigger. Процедурный энергетический WebGL-портал, пространственная галерея и пять интерактивных демонстраций. Системные шрифты не требуют внешних запросов. Анимации учитывают `prefers-reduced-motion`.

## Запуск

Требуется Node.js 22+ и npm.

```sh
npm install
npm run dev
```

Vite выводит адрес сервера в терминал. Для проверки публикации:

```sh
npm run build
npm run preview
```

Сборка находится в `dist`. В ограниченной облачной среде при недоступном стандартном кеше используйте `npm install --cache /tmp/nikolay-npm-cache`. Для повторяемой установки с lockfile можно использовать `npm ci`.

## Контакты

Скопируйте `.env.example` в `.env` и заполните:

```dotenv
VITE_TELEGRAM_URL=https://t.me/yuniorqq
```

Telegram по умолчанию — **@yuniorqq**, подтверждённый владельцем сайта. Он хранится в `src/config.ts` и выводится текстом и кнопкой. `VITE_TELEGRAM_URL` может переопределить его при публикации; пустая переменная сохраняет этот Telegram. Email не отображается: единственный канал связи — Telegram. Некорректное переопределение переменной сохраняет подтверждённый адрес @yuniorqq. Перезапустите dev-сервер или пересоберите сайт после изменения переменных. Переменные с префиксом `VITE_` публичны: не помещайте в них секреты.

## Проекты и контент

Проекты редактируются в `src/projects.ts`. Поля: `name`, `description`, `category`, `technologies`, `url`, `image`, `upcoming`. Для реального скриншота положите файл, например, в `public/projects/aura.webp` и задайте `image: '/projects/aura.webp'`. Желательно использовать WebP/AVIF шириной 1400–1800 px.

Для AURA BEAUTY сейчас показано **концептуальное превью, а не скриншот**: сайт недоступен из среды разработки из-за сетевого ограничения. Стек исходного проекта не подтверждён, поэтому он не выдуман. Замените превью настоящим скриншотом и заполните технологии после проверки. Карточка-заготовка не выдаётся за выполненный кейс.

Основной контент находится в `src/main.tsx`, стили — в `src/style.css`. SEO-заголовок и описание — в `index.html`. После появления домена можно добавить canonical и абсолютные `og:url` / `og:image`.

## Публикация на Netlify

1. Загрузите проект в свой GitHub-репозиторий и подключите его в Netlify через импорт существующего проекта.
2. Команда сборки: `npm run build`, директория публикации: `dist`. Эти настройки уже указаны в `netlify.toml` вместе с Node.js 22.
3. В настройках переменных окружения Netlify добавьте `VITE_TELEGRAM_URL`.
4. Запустите Deploy. После изменения переменных выполните новую сборку.

Также можно загрузить готовую папку `dist` через ручную публикацию Netlify. В этом случае контакты должны быть заданы перед локальной сборкой.

Это одностраничный сайт с якорной навигацией; дополнительный SPA redirect не требуется.


## Единственное космическое вступление

Сценарий: **одна чёрная дыра → погружение → полёт сквозь галактики → сайт**.

- `CosmicIntro.tsx` отвечает за показ один раз в сессии, «Пропустить», Escape, таймер защиты и плавное раскрытие страницы.
- `introJourney.ts` задаёт единую временную траекторию на 6.35 секунды. На стыках непрерывна скорость камеры: короткая пауза, ускорение к горизонту, быстрый полёт, торможение.
- `PortalScene.tsx` использует один Canvas. Процедурный диск из `BlackHole.tsx` плавно уступает место другому трёхмерному миру: звёздам, следам, трём туманностям и пяти спиральным галактикам из частиц на разных расстояниях. Камера проходит 133 условные единицы; это не масштабирование картинки.
- Последние 1.1 секунды — прибытие: следы сокращаются, камера замедляется, основной экран проступает под интро. Основной портал подключается после удаления Canvas интро. Вспомогательные WebGL-сцены при раскрытии приостановлены.
- Диск вычисляется в полном разрешении Canvas. DPR ограничен 1 на мобильных/слабых устройствах и 1.25 на desktop. Упрощённый режим использует меньше частиц галактик, звёзд и выборок свечения. Для программного рендерера и устройств с двумя ядрами диск сохраняет полное разрешение и линзирование, но использует более лёгкую процедурную структуру газа с антиалиасингом нитей.
- При `prefers-reduced-motion`, прямой ссылке на секцию или повторном открытии в той же сессии сайт доступен сразу. В отключённом хранилище работают пропуск и защитный таймер. Ошибки WebGL/шейдера, потеря контекста и зависшая загрузка освобождают страницу.
- После интро геометрия, материалы и буферы портала освобождаются. Повторных тоннелей, чёрных дыр и проходов при прокрутке нет.

Для повторного просмотра очистите ключ `nikolay-portal-seen-v1` в sessionStorage или откройте новую сессию браузера.

## Основной сайт и общий фон

В `Scene.tsx` подключён самостоятельный энергетический портал `HeroPortal.tsx`: семь спиральных лент, два прозрачных слоя воронки, четыре независимо вращающиеся световые дуги и 720 частиц (240 в мобильном режиме). Четыре draw calls, BufferGeometry и процедурное свечение без bloom-проходов и текстур. Это отдельная футуристическая структура без аккреционного диска и горизонта событий. Курсор мягко наклоняет объект и смещает камеру; после остановки мыши влияние затухает. При прокрутке портал только растворяется. `useCinematicFlow.ts` измеряет защищённую область портала и анимирует заголовки/секции. Hero имеет обычную высоту экрана; сразу за ним идут проекты, без пустого закреплённого пролёта.

`AmbientBackground.tsx` — общий Canvas 2D: мелкие звёзды нескольких глубин, мягкие серебристые туманности и редкие спиральные галактики. Галактики генерируются из тех же процедурных частиц, что и во вступлении. Мягкий параллакс сохраняет читаемость текста. Когда активен WebGL-объект, фон обновляется реже; это не второй тяжёлый 3D-рендерер. PAUSE и reduced motion останавливают движение, скрытая вкладка прекращает непрерывный рендер.

`useSceneBudget.ts` разрешает непрерывную анимацию одному видимому 3D-объекту. Остальные сохраняют кадр и возобновляются при приближении/наведении. Сохранены пространственная галерея проектов, хромированный узел, стеклянный многогранник, анимации текста и все контакты.

## Белый кубик Рубика

`AccentScene.tsx` вращает весь кубик со скоростью 0.0975 рад/с по основной оси — в 1.5 раза быстрее прежней. Скорость рассчитывается через delta time, без React setState на кадрах. При возобновлении после паузы первый delta пропускается, чтобы положение не прыгало.

`RubikController` в `rubikModel.ts` поворачивает слой за 1.4 секунды с паузой 4.8 секунды. Плавная кривая поворота имеет нулевую скорость на краях; остаток времени переносится через границы фаз. `rubikRig.ts` вращает временную группу из девяти деталей, загружая instance-матрицы только на границах поворотов. Все 54 внешние наклейки белые, разделители тонкие и чёрные. На слабых устройствах и программном WebGL кубик использует более лёгкие матовые материалы с освещением (Lambert); на аппаратном desktop сохраняется PBR. Кнопок управления кубиком нет. На desktop кубик увеличен на 12% и приближен к центру композиции; мобильная колонка и Telegram сохранены.

## Проверка

```sh
npm run test:models
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:intro
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:browser
```

В обычной системе можно установить Chromium командой `npx playwright install chromium` и не задавать `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

`test:intro` сам запускает dev-сервер на 5177, проверяет четыре этапа, настоящий вывод звёзд/галактик, размер буфера диска, переход, desktop/mobile, повторный вход, пропуск, reduced motion и ошибки графики/загрузки. Для уже запущенного production preview задайте `INTRO_TEST_URL=http://127.0.0.1:4173`. Снимки сохраняются в `/tmp`.

`test:browser` поднимает dev и production, проверяет обычную прокрутку без повторного портала/пустого пролёта, меню, контакты, галерею, взаимодействие с объектами, GPU-группы кубика и независимые fallback. Тесты моделей проверяют непрерывность траектории, отсутствие пустоты на стыке миров, целостность кубика и независимость поворотов от частоты кадров.

Короткий профиль hero-портала и кубика (нужен запущенный preview):

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run profile:scenes -- sample http://localhost:4173
```

Профиль сохраняет JSON с длительностями кадров и PNG во временную папку; путь можно изменить через `NIKOLAY_PROFILE_DIR`. Облачный Chromium использует программный WebGL: его замеры не подтверждают FPS на физических телефонах. Актуальные результаты и ограничения проверки — в `docs/QUALITY_REPORT.md`; сырые профили и архив старых измерений — в `docs/scene-measurements.json`.

```sh

```

Скрипт проверяет HTTP-доступ и название бренда перед сохранением снимка, а затем записывает WebP и происхождение в `public/projects`. Пустой манифест по-прежнему намеренно не проходит `check:captures`; это не проверка вступления.

Проверка нового hero (сначала запустите dev на 5190): `HERO_TEST_URL=http://127.0.0.1:5190 PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium node scripts/check-hero-portal.mjs`. Проверяет GPU-время, курсор/возврат, четыре draw calls, уменьшение числа частиц на mobile, раздельные области текста/3D, паузу, reduced motion и консоль.
